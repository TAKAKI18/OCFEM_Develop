## 原本一致

Fortran原本12本と入力例7ファイルについて、ファイル名とバイト列を保存し、SHA-256の完全一致を確認しました。登録用のFortranソースへのコメント追加、改名、数式変更、改行変換は行っていません。履歴上の旧アップロードとの比較は`UPLOAD_AUDIT.md`を参照してください。

- 断面重みが定数1を積分して両方向とも1となること。

## 検出された原本の問題

### 疎行列組立モジュールの境界チェック失敗

`test_sparse_triplet_builder`は配列境界チェック付き実行で失敗しました。`src/common/sparse_triplet_builder.f90`の216行で、`SORTED_COL(6)`を要素数5の配列に対して参照しています。

該当する原本の条件は次のものです。

```fortran
do while (k2 <= end_pos .and. sorted_col(k2) == sorted_col(k))
```

Fortranでは`.and.`の右側を必ず評価しないという短絡評価は保証されません。原本一致を優先する今回の整理では修正していません。試験失敗を成功へ書き換えず、`tools/check_runtime.py`も失敗終了を返します。

### Windows上での大容量Stokes原本のコンパイル制限

大きい配列上限を持つ原本のStokesソースを通常構成でコンパイルすると、`COLMAT1`が2GBを超えて`error #5656 ... too large for NTCOFF`となります。`smoke`の検証用コピーは`KNAA=256`のためコンパイルできました。`/heap-arrays`だけでは原本の巨大COMMONブロックは解消しません。今回、原本の配列設計を変更していません。

## 範囲

NSの本計算・時間発展計算は開始していません。非線形収束、空間・時間の収束性、圧力・流量の物理解の妥当性を今回新たに保証するものではありません。原本を正しく配置したことと、数値計算上の問題の解決とは区別します。
